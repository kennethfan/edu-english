## 0. 一句话结论

**可行且个人身份能上线**：原生重写界面层（约 5–7 个工作日），26 册数据与发音音频按「册」拆分包（总包 30M 装得下 15–18MB 音频），零服务器、零域名备案依赖，走「工具-效率」类目。

```
miniapp/
├── app.json                  # 主包 + 13 个分包声明（脚本自动生成）
├── pages/
│   ├── index/                # 选册页（主包）

│   └── store.js              # 进度存取（wx.setStorageSync）

    ├── b03-b04/
    └── ...共 13 个
```

### 关键技术点

| # | 问题 | 方案 | 风险 |
|---|---|---|---|
| 1 | 主包游戏页要读分包数据 | **分包异步化** `require.async()`（基础库 ≥2.17.3） | 低，官方特性 |
| 2 | 分包静态音频跨包播放 | `InnerAudioContext.src` 指向分包绝对路径，进入前 `wx.preDownloadSubpackage` | **中，M0 必验**；不行则降级云存储 |
| 3 | iOS 不认 ogg | 全量转 **mp3 16kbps**（~2KB/条，总 ~18MB，仍在 30M 内） | 无，现有 `.work/raw` 可直接重转 |
| 4 | 单分包 ≤2M | 每册 ≈ 音频 0.7MB + 数据 0.07MB → **2 册/分包 ≈ 1.6M**，26 册 = 13 分包 | 低；若超限改 1 册/分包 |
| 5 | 音效（原 AudioContext） | `wx.createWebAudioContext`（≥2.19）或 3 个短 mp3 | 低，M0 顺带验 |
| 6 | 进度持久化 | `wx.setStorageSync`（上限 10MB，进度数据 <50KB） | 无 |
| 7 | 连播节奏 | `InnerAudioContext.onEnded` ↔ 原 `u.onend`，契约等价移植 | 无 |

## 3. 数据管线（复用现成脚本）

新增 `scripts/make-miniapp-pkgs.py`：
1. 从 `www/index.html` 抽取 `__WORD_MATCH_DATA__`（现成解析逻辑在 `make-audio.py`，直接复用）
2. 每册输出 `data.js`（模块化导出，key 压缩：`{k,en,zh}` → `[k,en,zh]` 数组，体积再省 ~40%）
3. `.work/raw/*.mp3` 按哈希索引重转 **mp3 16kbps**（`--transcode-only` 思路复用，~5 分钟全量）
4. 按册归包 + 自动生成 `app.json` 的 subpackages 段
5. 校验：每个分包实测体积 ≤1.9M、哈希抽查 20 条与 `audio-index.tsv` 对得上
